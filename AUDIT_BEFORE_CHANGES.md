# Предварительный аудит NovaMind-v2

## Краткий вывод

Статический аудит обнаружил два риска **P0**, позволяющих неаутентифицированному клиенту выполнять Python-код на сервере и получать конфигурацию AI-провайдеров с возможными действующими ключами. До исправления этих проблем публичное развёртывание нельзя считать безопасным. Дополнительно выявлены межпользовательский доступ к документам, SSRF, небезопасное исполнение терминальных команд, риск использования provider credentials самим тестовым набором и уязвимости загрузки файлов.

Аудит проведён до исправления кода по всем основным контурам: Flask/API и идентичность, агент/инструменты/MCP/поиск, хранилище/загрузки, AI-провайдеры, frontend, CI и документация. Локальные значения `.env`, API-ключи, cookies и другие секреты не выводились и не копировались. Выводы статические; фактическая production-конфигурация и внешняя инфраструктура не проверялись.

## Проблемы по приоритетам

### P0 — немедленно закрыть

1. **Admin API не требует admin-сессии.** `routes/admin.py` не задаёт общий `before_request`-guard; в частности, `POST /api/admin/run_saved_code` запускает сохранённый Python-файл через `subprocess` (`routes/admin.py:257–288`). `routes/__init__.py:24–43` регистрирует blueprint без внешнего admin guard. Независимый сетевой клиент может сохранять и запускать код с правами серверного процесса. **Риск:** удалённое выполнение кода и потенциальная компрометация сервера.
2. **Неаутентифицированный admin stats раскрывает объект `PROVIDERS`.** `GET /api/admin/stats` сериализует весь `config.PROVIDERS` (`routes/admin.py:220–232`); конфигурация содержит ключи в заголовках и URL (`config.py:116–186`). Из-за отсутствия admin guard это может раскрыть действующие credentials. **Риск:** кража ключей, злоупотребление внешними API и расход квот.

### P1 — высокий риск

- **Непроверенный Google ID token:** callback декодирует JWT payload без проверки подписи, issuer, audience, nonce и `email_verified`, затем доверяет email (`routes/admin.py:63–108`). Возможна подделка пользовательской идентичности.
- **Fail-open endpoint `/run`:** при пустом `AGENT_TOKEN` проверка пропускается (`app.py:90–106`), хотя приложение слушает все интерфейсы (`app.py:117`). Возможны неавторизованные запросы к AI-провайдерам.
- **Секрет admin-кода в логах:** при отсутствии `ADMIN_CODE` код генерируется, затем записывается в лог (`config.py:103–114`, `app.py:109–117`).
- **Небезопасный bootstrap pytest:** `tests/conftest.py:11` импортирует `config` до того, как autouse fixture удаляет provider-key переменные (`tests/conftest.py:22–36`). `config.PROVIDERS` материализует ключи при импорте (`config.py:116–186`); тест, делающий сетевой запрос, может унаследовать credential из окружения CI. **Риск:** незапланированная отправка данных/платный вызов во время тестов. Первую попытку baseline остановили во время TLS-handshake; она не считается валидным результатом. Полный повтор выполнен с очищенным окружением и блокировкой внешней сети.
- **Терминал исполняет произвольный код на host:** разрешены Python/Node и другие интерпретаторы; команды запускаются с окружением и filesystem сервера (`routes/terminal.py`). Нет OS/container sandbox; прямой HTTP route также обходит подтверждение опасных действий (`agent/policy.py`, `routes/terminal.py`). Сетевые утилиты позволяют произвольный egress. Это не изоляция выполнения.
- **SSRF в web fetch:** `fetch_page_text` принимает произвольные HTTP(S)-адреса и следует редиректам без проверки частных/loopback/link-local адресов (`routes/search.py:926–947, 1102–1127`).
- **Межпользовательская утечка знаний:** tool `knowledge_search` не связывает запрос с owner, поэтому пустой scope допускает поиск документов всех владельцев (`tool_registry.py:329–340`, `knowledge.py:413–436`).
- **Публичные загрузки и активный SVG:** `/api/media/upload` и `/media/<name>` не требуют владельца/авторизации, MIME доверяется клиенту (`routes/media.py:298–323`). Возможны раскрытие файлов и same-origin stored XSS через SVG.
- **Неограниченный платный TTS fan-out:** длинный пользовательский текст разбивается на части без лимита и порождает множество сетевых запросов (`media_generation.py:1186–1232`). Возможны расходы/исчерпание квоты.
- **Raw chain-of-thought в потоках:** `routes/chat.py` и `routes/search.py` передают reasoning chunks клиенту без редактирования (`ai_providers.py` также сохраняет reasoning-поля провайдера).
- **Composio action без отдельного подтверждения:** admin endpoint принимает имя действия и параметры, после чего сразу запускает его (`routes/composio.py:91–111`). Компрометация/CSRF admin-сессии может привести к изменению внешних аккаунтов.
- **DOM XSS в admin списке файлов:** имя файла вставляется в inline `onclick` без корректного JavaScript-экранирования (`templates/admin.html:513–525`). Исправление admin-аутентификации снижает публичную достижимость, но не устраняет дефект.

### P2 — существенные ограничения безопасности/устойчивости

- Клиент может задавать для прямой terminal-команды чрезмерный timeout без жёсткого верхнего предела (`routes/terminal.py:943–989`), занимая ограниченные слоты исполнения.
- Валидатор аргументов MCP реализует лишь подмножество JSON Schema и принимает некоторые неподдерживаемые/слишком глубокие схемы (`mcp_registry.py:912–947, 1070–1084`).
- Нет endpoint-specific upload quotas; общий Flask request limit равен 500 MB, проверка фактического размера может происходить после записи. Для OOXML/PPTX не ограничены распакованный объём, число элементов и compression ratio (`app.py:30`, `routes/media.py`, `routes/ops.py`, `knowledge.py`). Возможны disk/CPU/RAM DoS.
- Media jobs копятся в глобальном реестре без TTL/лимита; статусы custom media endpoints могут выводить URL с query-секретами (`media_generation.py:1560–1577, 1685–1717`).
- Frontend экранирует HTML, но вставляет невалидированные URL в `href`/`src` и не валидирует URL аватара (`static/app.js`).
- Не заданы централизованные CSP, `X-Content-Type-Options`, frame protections и явные session-cookie flags (`app.py`).
- CI запускает compileall/pytest и ограниченные smoke checks, но не задаёт lint/type/dependency/security gates; зависимости не зафиксированы lock-файлами (`requirements*.txt`, `package.json`, `.github/workflows/`).
- **Тест изменяет tracked артефакт:** `tests/test_turtle_headless.py` записывает GIF-пример в `examples/turtle_spin/spin.gif`, меняя бинарный файл в рабочем дереве после тестов. Нужно перенести результат теста в `tmp_path`.

### P3 — точность и сопровождаемость

README содержит устаревшие версии Python/Flask, противоречивые лимиты загрузки и ссылки на отсутствующие файлы (`README.md`; фактические лимиты/версии задаются `app.py`, `requirements.txt`, `render.yaml`). Документация не даёт целостной карты угроз, операций, миграций и deployment-ограничений.

## Существующие меры защиты

Есть тестируемые ограничения traversal и владельца для ряда workspace/chat маршрутов; allowlist команд, запрет shell-chaining, лимиты ReAct-шагов и повторов, классификация MCP-действий, базовый rate limiting, ротация ключей Groq, параметризованные SQLite-запросы, некоторые проверки размеров изображений и secret-pattern фильтр памяти. Эти меры полезны, но не заменяют общую авторизацию, sandbox и ограничения внешнего ввода.

## План исправления

1. Закрыть все чувствительные admin endpoints общей серверной проверкой, убрать secrets из admin JSON и логов, запретить fail-open `/run`; добавить отрицательные тесты на неавторизованный доступ.
2. Исправить bootstrap тестов: очищать provider credentials до импорта модулей конфигурации и блокировать внешнюю сеть в CI; использовать временные пути для всех тестовых артефактов.
3. Закрыть межпользовательский доступ и сетевые границы: owner-scope для knowledge tools, SSRF-проверки до/после редиректов, подтверждение Composio actions, явная схема доступа к upload/download.
4. Сократить поверхность исполнения: отключить небезопасный host-terminal fallback, запретить произвольные interpreter/network commands вне настоящего sandbox, ограничить timeout/resources; не заявлять полноценную изоляцию без OS/container boundary.
5. Добавить лимиты и redaction для TTS/media jobs/custom URLs; прекратить выдачу raw reasoning; устранить DOM XSS/опасные URL и усилить security headers/cookies.
6. Укрепить CI: pytest + coverage, Ruff, type-check, Bandit, pip-audit, frontend smoke и secret scan; синхронизировать документацию и итоговый отчёт. Каждый этап сопровождается targeted regression tests и записью в CHANGELOG.

## Внешняя инфраструктура и риски, не решаемые только кодом

- Полноценный sandbox терминала требует отдельного непривилегированного runtime с ограничениями CPU/RAM/processes/syscalls/filesystem/network (например, корректно настроенного container runtime или отдельной VM). В текущем окружении Docker недоступен; нельзя обещать полноценную изоляцию только Python-проверками путей.
- PostgreSQL/Alembic, Redis/distributed rate limiting/jobs, worker pool, S3-compatible private storage и антивирусный сканер требуют инфраструктуры, секретов, миграционного/backup-плана и отдельных operational решений.
- HSTS/TLS, egress policy, proxy-aware IP handling и публичная CORS allowlist должны быть согласованы с фактическим production reverse proxy/доменом.
- Production deployment, GitHub secrets и платные внешние сервисы этим аудитом не меняются.

## Baseline

Полные исходные результаты, команды и ограничения записаны в `BASELINE_TEST_RESULTS.md`. Безопасный повтор прошёл все имеющиеся тесты в очищенном окружении с запретом внешней сети; исходная попытка, остановленная во время TLS-handshake, в результаты не включена.
